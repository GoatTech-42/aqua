auto-reorder
proposed free-route swaps; pinned models stay unchanged.
how auto-reorder works
when on, a background job (every 10 min) can swap adjacent routes. a swap needs a contender with at least 30 measurements in the last 24 h. score means measured speed on healthy, complete responses. a contender only counts if it is an eligible free route that fits the request size and passes access and privacy checks. close calls go to the route with more quota headroom. it must score 25% better twice in a row. the model must not have moved for an hour. the rules are intended to reduce order changes caused by noise. one adjacent swap per evaluation. a route demoted for poor health still gets an occasional probe request. that is about 2% of traffic, so it can be measured again. probes only use otherwise eligible free routes. a route is skipped while its pool cools down, when access or privacy rules exclude it, or when the request would not fit its limits. models you reorder by hand are pinned and left alone, probes included. every move, yours or automatic, lands in the change log with the numbers behind it. proposed defaults - not yet tuned on real traffic.

models

one row per model. this page orders providers for a model you already picked; choosing the model itself is a separate proposed feature and is not live. the first eligible route is tried, then eligible same-model free backups; if none remains, the request should fail with a clear reason - never a silent paid, trimmed or different-model answer (proposed behavior, not yet live). order source is labeled. config is registry order. auto-adjusted means the auto job moved it, with the numbers in the change log. yours means pinned.
